# Pith v3.0.7

This is the first public v3 release, combining accepted changes from v3.0.0 through v3.0.7 since v2.4.8. Review the breaking change before upgrading; `pith update` can offer newer major versions.

**Breaking: Thneed integration removed (v3.0.0).** Pith no longer registers the specialized Thneed parser, exports the Go `ThneedParser` type, or runs Thneed to enrich diagnostics. An independently installed Thneed command can still be wrapped, but receives general processing rather than the removed Thneed summary format. Existing parser settings cannot restore it. No replacement retrieval engine is included. Explicit `pith audit anomalies --diagnose` still requires `--allow-external-ai` to send bounded, redacted diagnostic snippets to Gemini; diagnostics are not offline.

**Exit statuses, raw output and omission accounting (v3.0.1–v3.0.3).** Normal child numeric exit statuses now reach the CLI unchanged, including silent failures and failures with success-looking output. Explicit `pith raw` returns all captured stdout followed by all captured stderr with no inserted separator, parsing, or truncation, including output above `MaxLines`. Middle-Out truncation reports every omitted segment with its exact line count, including single-line gaps, while retaining selected lines once and in order. A final newline terminates the last line rather than becoming an extra tail line; actual blank lines and the final newline are retained.

**Execution failures preserve captured output (v3.0.4).** When a command executed by Pith's direct runner returns an error, the runner bypasses parsers and truncation and emits the complete captured stdout-plus-stderr representation. Silent failures cannot acquire parser-generated success text, and captured late diagnostics are retained. These failures record protected passthrough with no parser and equal before/after token estimates. This does not recover output absent from the capture, change successful-command compression, or extend that bypass to the legacy `_hook` path.

**Conservative parser fallbacks (v3.0.5).** Git status, test and Go coverage parsers preserve empty or unsupported captures instead of manufacturing success, test completion, or aggregate 100% coverage. Git captures without recognized human-readable context retain their whitespace, including empty machine-readable status output; this is not evidence of a clean whole worktree. Structured-looking complete or malformed JSON in those line-oriented parsers stays intact. Recognized summaries retain existing processing. Pi transform fallbacks retain passthrough provenance while still applying mandatory redaction.

**Incomplete composite Git and Git show records (v3.0.6).** Composite Git and Git show parsing preserves the entire original capture when a commit record or following section boundary is incomplete or unsupported, instead of panicking on shortened dates or inventing partial summaries. Only complete default-format single-subject commit records are condensed; multiline messages, merge/signature metadata and unsupported formats remain intact. Non-commit-shaped Git show captures, including ordinary blobs and annotated tags, pass through. GitShow dispatch is limited to default `git show` and `git show HEAD`; other selectors/options bypass that parser because their object type cannot be established without a lookup. Supported simple commit/diff compression remains. Recognized diff/status boundaries retain existing section processing; this is not validation of complete patches or status inventories.

**Release delivery correction (v3.0.7).** This fresh version supersedes unpublished v3.0.6, whose source tests, native package smokes and validation passed but whose release job was skipped before signing or publication. Its original tag remains unchanged. The release condition now explicitly allows a non-cancelled tag push only after both native builds and aggregate validation succeed, accommodating the intentional Windows-link skip on tags. Signing, verification and immutable publication safeguards remain unchanged; no manual recovery route or retry of v3.0.6 is introduced.

**Output and privacy boundaries.** Raw and failed-command output combines child streams onto stdout, without preserving separate destinations or temporal interleaving. Pith's own error/usage diagnostics may still appear on stderr. Preserved output can be large. Successful commands still use ordinary truncation, including parser bypass, disabled parsers and unsupported-parser fallbacks; parser-level preservation does not promise an untruncated final CLI result. Generic wrapper errors and Unix signal termination retain exit 1; signal forwarding, `128 + signal`, and changed shell semantics are not provided. Omission counts describe Middle-Out's input, not recovery of content a parser already discarded. No universal parser completeness, upstream-output recovery, performance or model-quality improvement is claimed. GitStatus inventories are unchanged: this release excludes the separately prepared, unpublished Git-status inventory, du/filesystem-fidelity and additional structured-output parser changes.

Existing surface-specific privacy policies remain: CLI raw/failure passthrough is not a redaction guarantee, Pi transform still redacts, telemetry consent controls remain unchanged, and newly recorded/imported raw-content fields and exports remain empty. Diagnostic command/output logs remain opt-in; their heuristic redaction cannot guarantee removal of every secret. No new raw-output retention is enabled.

**Packages and verification.** Native packages cover Linux amd64, Windows amd64 and macOS arm64. Each actual package receives focused smoke tests; this is not a full Windows/macOS suite or support for other architectures. The release includes those three binaries, `checksums.txt`, `checksums.txt.sig` and `sbom.cdx.json`. The SHA-256 binary checksum manifest is signed and verified against the updater's embedded production public key. The signature authenticates the manifest and its three binary hashes, not the CycloneDX SBOM. No Authenticode signing or Apple notarization is claimed. The publication workflow requires these reviewed notes and verifies their exact text and all six assets' names, sizes, uploaded states and SHA-256 metadata before and after publication.
